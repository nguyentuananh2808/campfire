# Operations

The API writes compact structured JSON logs and includes trace IDs in ProblemDetails. Liveness and readiness routes exist; readiness checks module databases against PostgreSQL. Production must set `Security__RequireHttps=true`, an explicit semicolon-separated `AllowedHosts`, and a persistent `DataProtection__KeysPath`; startup exits nonzero if any prerequisite is missing. Terminate TLS at a trusted edge, list its private address under `ReverseProxy__KnownProxies__0`, rotate logs and keep PostgreSQL private. Do not trust forwarded headers from arbitrary networks.

Release order is backup/check → start PostgreSQL/LiveKit → run the one-shot migrator → start API/web → smoke health and critical journeys. The migrator reads `ConnectionStrings__Campfire` and applies every module schema, including Stranger Chat. Database rollback is not assumed; breaking changes use expand/contract. Local Compose binds PostgreSQL port 5433 to loopback only. It also builds a pinned-digest .NET API/migrator image; the migrator must exit successfully before the API starts. The current Development-only LAN mapping is `192.168.5.185:92 -> 8080` and must not be reused as an Internet-facing production edge.

Swagger UI and `/api/openapi/v1.json` are Development-only. Production API responses are marked against framing/type sniffing and private `/api/v1` responses use `no-store`; configure equivalent CSP/frame/referrer/permissions headers on the Angular static-file host. The sample values in `.env.example` are placeholders and must be replaced through a secret store or deployment environment, never committed as real credentials.

Werewolf voice requires `LiveKit:PublicUrl` (browser WebSocket URL), `LiveKit:ApiUrl` (server HTTP API URL), `LiveKit:ApiKey` and a secret of at least 32 bytes. Local Compose pins LiveKit `v1.13.10` on 7880/7881 and UDP 50000–50020. Production must use TLS, a public DNS name, firewall/NAT rules and TURN for restrictive networks; never reuse local credentials. Recording/egress is intentionally not configured. Health, metrics, capacity and multi-device audio must be validated before public rollout.
