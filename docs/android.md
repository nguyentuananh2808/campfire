# Campfire Android

## Architecture

The Android client is a Capacitor 8 native shell in `frontend/android`. It opens the canonical production origin `https://tamsuvoinhau.cloud` inside the Android WebView.

This is intentional for the first Android release:

- the existing relative `/api` and `/hubs` URLs remain same-origin;
- Identity cookies, antiforgery and SignalR keep their current security model;
- the Android UI receives the same deployed mobile improvements as the web app;
- no CORS relaxation, JavaScript auth token or duplicate mobile API client is introduced.

The trade-off is that the first release requires a network connection and is coupled to production availability. Capacitor documents `server.url` as a live-reload option rather than a production-store architecture, so this shell is suitable for the requested sideload/test APK but must not be submitted to Google Play unchanged. A future Play release should use a verified Trusted Web Activity/PWA or a bundled client with a dedicated mobile authentication design.

## Requirements

- Node.js 22 or newer.
- Android Studio 2025.2.1 or newer.
- Android SDK Platform 36 and Build Tools installed from Android Studio's SDK Manager.
- An Android 7.0/API 24 or newer device; API 26 or newer is preferred for current WebView behavior.

## Build a debug APK

From `frontend`:

```powershell
npm ci
npm run android:apk
```

The APK is written to:

```text
frontend/android/app/build/outputs/apk/debug/app-debug.apk
```

Install it on a USB-debugging device with:

```powershell
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Use `npm run android:open` to open the generated native project in Android Studio.

## Release signing

Do not commit a keystore or passwords. Create a private upload keystore, configure signing through local Gradle properties or the release pipeline's secret store, then run `gradlew.bat assembleRelease` or build an Android App Bundle for Google Play. The debug APK is for device testing only.

## Direct APK updates

The Android shell checks `/app-updates/android.json` on startup and whenever the application resumes. It compares the manifest's `latestVersionCode` with Android's native `versionCode`. A newer valid manifest displays release notes and opens only an HTTPS download hosted at `tamsuvoinhau.cloud`; Android still requires explicit install confirmation.

For each release:

1. Increase `versionCode` and `versionName` in `frontend/android/app/build.gradle`.
2. Build the release APK with the same private signing key as every previous release. Android rejects an update signed by a different key.
3. Publish the APK under `https://tamsuvoinhau.cloud/downloads/`.
4. Update `frontend/public/app-updates/android.json` last, setting the new code/name, download URL and short release notes. Increase `minimumSupportedVersionCode` only for a genuinely incompatible or security-critical release.

The committed manifest describes version 1 and has no download URL, so development builds do not display a fake update. The remote Angular UI itself continues to update with the production web deployment; the APK flow is needed only for native shell/plugin changes.

## Security and permissions

- Cleartext HTTP and Android backup are disabled.
- The shell targets only the HTTPS production origin.
- `CAMERA` supports image capture from chat's file picker.
- `RECORD_AUDIO` supports learning pronunciation capture.
- Permission prompts appear only when the corresponding browser feature is used.

## Message notifications

- Android 13+ notification permission is requested after an authenticated Group Chat connection or an active Stranger Chat connection is established.
- New peer messages create a private Android notification with the system sound, vibration, Campfire status icon and current unread count. Message text, sender, group name and guest identifiers are deliberately excluded from the lock screen.
- Tapping a notification opens `/chat` or `/stranger`. Reading the conversation removes notifications tracked for that scope; logout clears the native notification tray.
- These notifications are generated by the active Capacitor WebView. They work while the application process remains alive, including when it is backgrounded, but cannot wake an application that Android has terminated.

Reliable killed-app delivery requires a later FCM increment: a Firebase project and `google-services.json`, a server-side device-token registry with per-user authorization/revocation, and post-commit push delivery. Those credentials and backend contracts are not present, so the app does not claim full push support.

Offline mode is not part of this first APK. Existing in-app sound, unread badges and page-title counters continue alongside native notifications while the WebView is active.

## Lock-screen vocabulary review

- `Học quanh lửa` exposes an Android-only opt-in control after a lesson has supplied vocabulary.
- The app keeps at most 100 public course words in origin-scoped local storage. It does not store credentials, learner answers or private content for this feature.
- Enabling the feature creates a silent, low-priority, public Android notification channel and an ongoing notification containing one Chinese word, pinyin and Vietnamese meaning. Tapping it opens `/learning`.
- `DeviceUnlockPlugin` listens for `ACTION_USER_PRESENT` with a runtime receiver and rotates the word when Android reports an unlock while the Campfire process is alive. App resume also rotates the word.
- Android does not deliver this runtime receiver after the process has been killed and may defer broadcasts for cached apps. The current notification remains visible, but rotation on every unlock is not guaranteed. Campfire intentionally does not add a battery-consuming foreground service or alter the user's wallpaper.
- Users can disable the feature in Learning and can independently hide lock-screen notification content in Android system settings.

This change includes native Android code and therefore requires APK version `1.1` (`versionCode 2`) to be rebuilt and installed; updating only the hosted web frontend is not sufficient.
